Data Flow

StepActionSecurity control
1 · InitUser selects department + file; browser requests an upload session.Upload record created in status container.
2 · ChunkFile sliced into 8 MiB blocks, 4 uploaded in parallel to the broker.Blocks staged straight into quarantine over the private endpoint; nothing buffered.
3 · CommitBroker commits the block list and launches the scan.Exactly one isolated job per file, upload ID injected.
4 · ScanEphemeral container runs open-source ClamAV.No inbound/outbound network; destroyed after scan.
5a · CleanFile promoted to its department container; quarantine copy deleted.Lands in sheriff / public-health / corrections.
5b · InfectedFile moved to infected; malware signature recorded.Department never receives the file.

Enterprise Security Controls

Network & Encryption

  • All blob traffic via private endpoint — never traverses the public internet
  • Compute is VNet-injected; storage has public network access disabled
  • TLS 1.2+ enforced end-to-end; HTTPS-only front door
  • Encryption at rest with Azure-managed keys

Identity & Access

  • No shared keys or connection strings anywhere in the solution
  • Managed identity with Azure AD tokens (auto-rotated)
  • Least-privilege RBAC: Blob Data Contributor, AcrPull, Jobs Operator
  • Storage is not reachable from the public internet at all

Malware Isolation

  • Open-source ClamAV — transparent, industry standard
  • One ephemeral container per file; no shared state
  • Scanner has no outbound network — cannot exfiltrate
  • Scan failure → file safely retained in quarantine

Data Governance

  • Lifecycle: quarantine purged after 7 days, infected after 30
  • Full audit trail per upload (state, timestamps, signature)
  • Per-department containers enable segregated access
  • Centralized logging in Log Analytics

Constraints & limits

  • Policy (enforced): storage public access disabled & shared-key auth disabled — both satisfied by design
  • Upload ceiling: ~400 GB (50,000 × 8 MiB blocks)
  • Scan ceiling: 2 GiB (ClamAV); larger files held in quarantine for manual review
  • Before production: add Microsoft Entra ID authentication and per-department authorization
